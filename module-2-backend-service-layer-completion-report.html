Possible Risks

RiskSeverityMitigation
Gemini API key not set Medium settings._require() raises RuntimeError at startup — server will not start silently broken. Message clearly names missing variable.
ORS API key not set Medium Same as above — hard startup failure with clear error message.
YOLO model file missing Low settings.YOLO_MODEL_PATH defaults to yolov8n.pt. Model loaded lazily on first request — error surfaced as 500 with logged traceback, not silent failure.
Currency YOLO model absent Low CURRENCY_MODEL_PATH defaults to empty string. CurrencyService.detect() silently skips YOLO and falls through to Gemini Vision.
Gemini transient error (scene/currency) Low SceneService has 1 retry with 1 s back-off. CurrencyService returns a graceful degradation response — never raises to the route.
Nominatim rate limiting Low NavigationService.geocode() logs warning and returns None → route returns 404 with a user-friendly voice_message.
Thread safety of MediaPipe FaceDetection singleton Medium Model is protected by _lock during initialisation. Inference itself is not lock-protected but MediaPipe is documented as thread-safe for inference. Monitor under load in Module 5.

Architecture Improvements — Summary

Problem (Before)Fix (After)
Routes contained 150–297 lines of mixed HTTP + AI business logic Routes are 9–50 lines of pure HTTP coordination (validate → delegate → return)
os.getenv() called on every HTTP request for API keys Keys read once from settings.* at service construction time
Mutable _GEMINI_CONFIGURED module-level global (not thread-safe) genai.configure() called once in SceneService.__init__
Gemini GenerativeModel instantiated per request Single model instance stored on service object, reused across all requests
navigation_history table existed but was never written to save_navigation() added to db.py, called from NavigationService.get_route()
Services package was an empty stub — no exports services/__init__.py exports all 5 singletons with __all__
Exception handlers used f-string logging (deferred formatting lost on error) All logging uses %-style lazy formatting (Python logging best practice)
Service classes have NO Flask imports — independently unit-testable Confirmed: zero Flask imports in any service file. Pure Python classes.
