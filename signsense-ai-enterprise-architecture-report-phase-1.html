3 All Problems Identified (Severity-Ordered)

Critical — Correctness / Security

C1
ORS API Key Hardcoded in Flutter Dart Code In navigation_service.dart: String.fromEnvironment('ORS_API_KEY', defaultValue: 'YOUR_ORS_API_KEY') — this embeds the key in the compiled APK binary. String.fromEnvironment is a compile-time constant; it does not read runtime environment variables on mobile. The default literal string ships in every release APK.
C2
Backend URL Duplicated in Two Flutter Files api_service.dart line 9 and detection_service.dart have separate hardcoded http://10.0.2.2:5000. Changing servers requires editing multiple files. No central config constant exists.
C3
SplashScreen First-Launch Check is a Stub _checkFirstLaunch() always returns true — every app launch shows onboarding. The SharedPreferences key set by AppProvider.setFirstLaunchComplete() is never consulted here.
C4
OCR / Scene / Currency Screens Initialize Camera Independently ocr_screen.dart, scene_description_screen.dart, and currency_screen.dart each call context.read<CameraProvider>().initializeCameras() in their own initState. If any screen is pushed while another has the camera open, it calls initialize again on an already-initialized controller, risking a platform exception.
C5
OCR Screen dispose() Calls stopImageStream() Unnecessarily ocr_screen.dart calls stopImageStream() in dispose but OCR never starts a stream — it uses takePicture(). This is a no-op but reveals the screen doesn't understand camera state, which will cause bugs when CameraProvider is shared between screens simultaneously.
C6
NavigationService Calls ORS Directly from Flutter All routing logic (Nominatim geocoding + ORS call) is implemented in Flutter's navigation_service.dart AND again in Flask's navigation_routes.py. Two completely separate implementations of the same feature. API keys, error handling, and parsing are duplicated. The Flask backend is bypassed for Flutter's navigation path.

High — Architecture / Maintainability

H1
No Clean Architecture Separation (Flutter) Business logic lives directly inside screen State classes. Example: _sendSOS() in sos_screen.dart handles GPS permission, location fetch, SMS construction, URL launching, and Share sheet — all in one method inside a Widget. This makes testing impossible and logic unreusable.
H2
No Service Layer on Flask Backend AI processing logic lives directly inside route functions. detection_routes.py calls get_yolo_model(), runs inference, formats response, and saves to DB — all in a single route function. No service layer means these cannot be unit tested, reused, or independently scaled.
H3
No Structured API Error Responses Error responses are inconsistent across endpoints. Some return {"error": "..."}, others return HTTP 500 with a Python traceback. No standard envelope (e.g. {"success": false, "error": {"code": ..., "message": ...}}) exists. Flutter screens do unguarded dict access on error responses.
H4
VoiceFAB Uses String-Matching Command Routing voice_fab.dart does plain command.contains('object') matching. "I want to detect objects near the road" would match, but so would unrelated speech. No intent parser. Tamil voice commands are listed as supported in README but not implemented here.
H5
SettingsScreen TextField Uses Ephemeral Controller Without Dispose settings_screen.dart line 222 creates a TextEditingController inside build(): TextEditingController(text: appProvider.emergencyContact). This creates a new controller on every rebuild, leaking the old one. The controller is never disposed.
H6
No Feature Folder Structure (Flutter) All screens, services, models, and providers are flat in their respective directories. The Master Prompt requires a feature-based structure (features/object_detection/, features/navigation/ etc.) for scalability and independent team work.
H7
Backend config/ Directory Is Empty The backend/config/ directory exists but is empty. All configuration (API keys, model paths, debug mode, port) is loaded directly from os.getenv() scattered across 6 files. No central settings class. No environment validation on startup.
H8
No Input Validation on Flask Endpoints No middleware validates file size, MIME type, or JSON schema before reaching route handlers. A malformed request (e.g., a text file uploaded as 'image') goes straight into the AI pipeline and produces an uninformative 500 error.

Medium — UX / Completeness

M1
DetectionResult.voiceMessage Misses "close" Position The model's voiceMessage getter has a case 'close': branch, but compute_position() in image_utils.py never returns "close" — it only returns "left", "ahead", or "right". The proximity/danger concept is never surfaced to the user.
M2
CurrencyScreen Contains Voice Map Duplicated from Backend currency_screen.dart has a _currencyVoice map with denomination strings that are identical to DENOMINATION_VOICE in currency_routes.py. The backend already returns voice_message — the Flutter screen should use it directly instead of maintaining its own copy.
M3
No Loading / Empty / Error State Pattern Screens show different loading UI patterns: some use CircularProgressIndicator, some disable buttons, some show nothing. No shared LoadingWidget, EmptyState, or ErrorCard component exists. The Master Prompt explicitly requires all four states per screen.
M4
Tamil Language Not Implemented in Voice Commands README and Master Prompt list Tamil as supported. SettingsScreen includes ta-IN in the language dropdown. But VoiceProvider.startListening() hardcodes localeId: 'en_IN' regardless of the user's selected language.
M5
YOLOv8 TorchScript Model Not Used yolov8n.torchscript is present in the project root. Analysis (Task 1) confirmed it provides ~1.4× faster inference on CPU. The ai_modules/__init__.py loads the .pt format. The torchscript path is referenced in .env.example but the loader ignores it.
