2 Problems Identified

P1
No Google Maps — Only OpenStreetMap Tiles NavigationScreen uses flutter_map with raw OSM tile URLs. No Google Maps SDK, no autocomplete search, no turn-by-turn arrow overlays, no real-time traffic layer, no Street View.
P2
No Nearby Places / POI Detection Zero implementation of shops, hospitals, ATMs, pharmacies, or restaurants around the user. A blind user cannot ask "what is around me?" No Google Places API or OSM Overpass integration exists.
P3
No Shop / Storefront Recognition Pipeline OCR and camera detection are completely isolated. There is no combined pipeline: Camera frame → OCR reads sign → map cross-references location → AI confirms "you are in front of [Shop Name]".
P4
Camera Frame Conversion is Incorrect (Critical Bug) DetectionService._convertToJpeg() returns raw plane[0] bytes of a YUV420 frame sent as a JPEG. The Flask backend calls PIL.Image.open() on this data — this will crash or silently fail on Android real devices.
P5
No Obstacle-Aware Navigation The navigation route is a static polyline. There is no real-time obstacle detection fed back into routing. YOLO detects obstacles in CameraScreen but this data is never connected to the NavigationScreen.
P6
ORS API Key Hardcoded in Flutter (Security Risk) NavigationService uses String.fromEnvironment('ORS_API_KEY') which defaults to a literal string 'YOUR_ORS_API_KEY'. In production builds this key is embedded in the APK binary and exposed.
P7
Duplicate Routing Logic (Maintainability Risk) Route fetching exists in both Flutter (NavigationService) and Flask (navigation_routes.py) independently. Both call Nominatim + ORS separately. There is no single source of truth.
P8
No AI Conversational Interface The app is feature-siloed (8 separate cards). The goal is an AI companion like ChatGPT/Alexa. There is no unified chat/command interface where a user can say "Take me to the nearest pharmacy" and get a combined response.
P9
No Safe Route Guidance (Sidewalk / Footpath Preference) ORS foot-walking profile is used but no accessibility preferences (avoid stairs, prefer footpaths, wheelchair mode) are set. No pedestrian safety scoring exists in the route response.

3 New Architecture

New Design Principle — Unified AI Companion

All features feed into a single AI Companion Layer. The user interacts through one continuous voice + text conversation. The AI selects the right tool (navigation, OCR, detection, places) automatically, just like Alexa or Gemini.

5 New Modules

Backend — New Python Files

signsense_ai/backend/ai_modules/ai_companion.py

Gemini 1.5 Flash with function-calling (tool-use). Receives user text or voice transcript. Routes to: navigation_tool, places_tool, detection_tool, ocr_tool, scene_tool. Returns single unified voice_message response. Maintains per-session conversation history in DB.

signsense_ai/backend/ai_modules/shop_recognizer.py

Takes image + GPS coords. Runs EasyOCR to extract sign text. Runs YOLOv8 for business-class objects (storefront, signage). Calls Google Places Text Search with OCR text near user GPS. Returns shop name, category, distance, accessibility info.

signsense_ai/backend/ai_modules/obstacle_analyzer.py

Dedicated YOLOv8 inference on navigation frames. Classifies obstacles by proximity zone (immediate <1m, near 1-3m, far 3-5m) using bounding box size heuristics. Returns structured alert: obstacle type, position (left/center/right), urgency (high/medium/low).

signsense_ai/backend/api/places_routes.py

Blueprint for /api/places/nearby (Google Places Nearby Search by type + radius), /api/places/search (text search), /api/places/shop-recognize (shop fusion pipeline). All API keys handled server-side.

signsense_ai/backend/api/ai_companion_routes.py

Blueprint for POST /api/ai/chat. Accepts {session_id, message, image_base64 (optional), lat, lng}. Returns {voice_message, action_type, payload}. action_type can be: navigate, show_places, describe_scene, read_text, emergency.

signsense_ai/backend/utils/route_safety.py

Takes ORS route segments. Scores each segment for pedestrian safety: footpath availability (OSM tags), crossing points, road width. Returns safety_score per segment and reroutes via ORS if score below threshold.

API Key Security Strategy

  • Google Maps API key (Android) stored only in AndroidManifest.xml meta-data — not in Dart code
  • Google Places, Directions, Geocoding keys stored only in Flask .env — never shipped in APK
  • Flutter makes all Places + Directions calls via Flask proxy endpoints (existing pattern)
  • HTTP Referrer restrictions set on Google Cloud Console to prevent key abuse

Dual-Map Strategy (Recommended)

Keep both Google Maps (primary, richer features) and flutter_map/OSM (fallback when no API key or offline). User can toggle in Settings. This protects against Google API quota exhaustion.

9 Performance Optimization Plan

Frame Throttling — Backend

Current: every frame in stream is sent. New: token-bucket throttle at 2 frames/sec for obstacle detection during navigation. Use existing _frameQueued flag + timer reset.

Model Warm-Up

Move YOLO, EasyOCR, MediaPipe loading to Flask startup (not lazy on first request). Current cold-start on first API call is 4-8 seconds. Use app startup event to pre-warm all models.

Places API Caching

Cache nearby places results in SQLite for 5 minutes per GPS cell (50m grid). Current: zero caching. This reduces Google Places API calls by ~80% during a single navigation session.

Image Resolution Reduction

Send 320×240 JPEG (quality 70%) for real-time obstacle detection (speed). Send 640×480 for OCR and scene description (quality). resize_for_inference() already exists — just wire it to the camera stream.

Gemini Prompt Caching

For repeated scene descriptions (same GPS cell + similar frame), return cached Gemini response. Add image hash (MD5) → response cache in SQLite with 2-minute TTL.

TTS Queue Management

Current: VoiceProvider.speak() interrupts any ongoing speech. Add priority queue: URGENT (obstacle) always interrupts, NAVIGATION announcements queue, AMBIENT (places) only speak when idle.

Background Location Batching

Merge geolocator streams: CameraScreen, NavigationScreen, and PlacesProvider all currently request location independently. Centralize in LocationProvider — one stream, multiple listeners.

YOLOv8 TorchScript

yolov8n.torchscript already exists in the project root. Switch YOLO inference from .pt (Python) to .torchscript format for ~1.4x faster CPU inference with no accuracy loss.
